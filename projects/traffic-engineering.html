The engineering problem

Networks must carry multiple traffic demands without overloading individual connections. In this assignment, network nodes and links were represented mathematically so that routing cost, capacity and traffic flow could be studied.

Original assignment methods

  • Graph modelling: network nodes and bidirectional links with abstract costs and capacities.
  • Dijkstra's algorithm: shortest weighted route between a chosen source and destination.
  • Single-commodity flow (SCF): one source–destination traffic demand.
  • Multi-commodity flow (MCF): several concurrent demands, using linear programming concepts.
  • Statistical analysis: comparison of link utilisation and possible congestion points.

The coursework uses Python, NetworkX, SciPy/PuLP concepts and a GEANT2 topology. The historical report discusses optimisation and its trade-offs; the downloadable demo on this page independently re-creates shortest-path analysis from the CSV data.

Data and findings — important distinction

The uploaded GEANT2_Links.csv contains 32 nodes and 55 unique bidirectional links. The assignment brief describes 54 links, so the supplied CSV and the brief do not fully agree. This portfolio's reconstruction uses the provided CSV as-is.

The sample demand documented by the coursework is 250 Mbps from node 32 to node 1. With the supplied CSV, the weighted shortest path is the direct link 32 → 1 and its total cost is 5 (an abstract metric, not measured milliseconds).

The archived report also contains inconsistent example metrics and incomplete template headings. Rather than promote those figures as independently verified results, the demonstration here shows reproducible shortest-path output from the dataset. The full linear-programming solver results have not been reconstructed.

What I learned

This investigation brought together computer networking, Python programming, graph theory, optimisation concepts and the interpretation of network performance visualisations. It also illustrates why checking dataset dimensions and validating metrics matters when reporting engineering results.
